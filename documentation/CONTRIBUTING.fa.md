# مشارکت در داینر

کد و مستندات در این مخزن عمومی قابل بازبینی‌اند. برای تغییر پیشنهادی Issue یا Pull Request بسازید. این سند مجوز حقوقی تازه‌ای برای استفاده یا بازنشر کد تعیین نمی‌کند؛ فایل مجوز مخزن و مجوز وابستگی‌ها را جدا بررسی کنید.

## قبل از تغییر

مسیر صحیح را انتخاب کنید: hosted برای برنامه آنلاین، docs برای پیش‌نمایش و منوی عمومی، documentation برای راهنما. Python قدیمی مستقل است. رفتار پیاده‌نشده را در راهنمای کاربر آماده معرفی نکنید.

## قواعد تغییر

- فارسی ساده، راست‌به‌چپ و واحد صریح؛ تومان در ورودی، ریال در داده.
- جمع درصد و محاسبه مالی سمت سرور؛ به مقدار محاسبه‌شده مرورگر اعتماد نکنید.
- schema تغییر کرد: migration تازه و snapshot/journal متناظر؛ تاریخچه اعمال‌شده دست‌نخورده.
- تغییر انبار یا فروش: آزمون retry، کسری، rollback و جداسازی مجموعه.
- داده نمونه صریحاً فرضی؛ فاقد اطلاعات واقعی و credential.
- تغییر قیمت/درصد نباید گزارش تاریخی را بازنویسی کند.
- منوی مشتری نباید recipeSnapshot، هزینه، داده حساب یا موجودی خصوصی را منتشر کند.

## شرح Pull Request

مسئله و اثر آن، رفتار جدید، مسیرهای تغییر، تست اجراشده و محدودیت باقی‌مانده را کوتاه بنویسید. برای تغییر API مثال و برای تغییر فرمول نمونه عددی بدهید. build موفق را با QA مرورگر یا تست امنیت اشتباه نگیرید.

## نگهداری اسناد

پس از تغییر رفتار، راهنمای کاربر، API، محاسبات و وضعیت محصول مرتبط را به‌روز کنید. لینک نسبی به کد بدهید. هر ادعای خارجی با منبع و تاریخ همراه باشد. برای باگ مستندات، نام فایل و متن صحیح پیشنهادی کافی است.
