# آدرس‌های مستقل و ابطال فروش

هر بخش پنل یک مسیر واقعی در router برنامه دارد. مسیر `/app/[section]` با فهرست مجاز بخش‌ها تطبیق می‌یابد؛ مسیر ناشناخته 404 است. صفحه اصلی و /app به داشبورد تستی هدایت می‌شوند.

| بخش | مسیر |
|---|---|
| داشبورد | /app/dashboard |
| مواد | /app/ingredients |
| دستورها | /app/recipes |
| انبار | /app/inventory |
| ترکیب‌ها | /app/blends |
| فروش | /app/sales |
| منوی مشتری | /app/menu |
| ضایعات مستقل | /app/waste |
| نقشه راه | /app/roadmap |

پارامتر `mode=demo` یا `mode=real` محدوده را مشخص می‌کند؛ پیش‌فرض demo است. منوی کناری از Link واقعی و دکمه‌های میان‌بخش از router.push استفاده می‌کنند. عنوان صفحه و بازگشت پس از ورود از مسیر گرفته می‌شود. بخش و محیط با URL بازسازی می‌شوند، نه حافظه تب. داده فرم ثبت‌نشده با ترک صفحه حفظ نمی‌شود.

این مسیرها روی میزبان آنلاین اعمال شده‌اند. GitHub Pages نمونه مستقل است و هنوز انتخاب نقش آن با hash انجام می‌شود؛ پنل واقعی مدیر کل، صفحات بازاریابی و منوی slug پایدار مرحله بعدند. آدرس مستقل مجوز دسترسی ایجاد نمی‌کند.

## اصلاح ثبت اشتباه

در گزارش فروش، ابطال با دلیل و تأیید تولیدنشدن غذا انجام می‌شود. موجودی تمام تخصیص‌ها در batch به lot اصلی برمی‌گردد؛ فروش علامت voided می‌گیرد و audit از نوع sale_void ایجاد می‌شود. تکرار ابطال دوباره موجودی اضافه نمی‌کند. جمع گزارش روز اصلی فروش را کنار می‌گذارد و سابقه با دلیل نشان داده می‌شود. برای اصلاح، فروش صحیح تازه ثبت کنید. این قابلیت مرجوعی غذای آماده، استرداد بانکی یا اصلاح خرید نیست.

## اعتبارسنجی

build و TypeScript موفق؛ تست نگاشت ۹ مسیر در هر دو محیط، رد مسیر ناشناخته در تابع لینک، آزمون محاسبات و ابطال با rollback/retry اجرا شده‌اند. بررسی HTTP محلی به دلیل در دسترس نبودن اتصال به سرور توسعه کامل نشد؛ آزمون تعاملی مرورگر/عقب‌وجلو انجام‌شده ادعا نمی‌شود.
